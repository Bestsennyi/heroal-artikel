# heroal Artikel — Техническая дорожная карта

Документ фиксирует уже реализованный инженерный фундамент и системные задачи по архитектуре, производительности и надежности данных.

---

## ✅ Что уже сделано

### 1. Стандартизация базы данных (Google Sheets)
- Унифицированы имена всех листов в нижнем регистре: `artikel`, `farben`, `auskunft`, `benutzer`.
- Введена первичная колонка `id` во всех таблицах.
- Стандартизированы ключевые поля (`artikel_nr`, `system`, `bild_haupt`, слоты `bild_1`–`bild_4`).
- Языковые колонки каталога приведены к единому стандарту трех языков (`_de`, `_en`, `_ru`).

### 2. Бэкенд и медиа-хранилище (Google Apps Script & Drive)
- Развернут `gas/Code.gs` (v4) с динамическим поиском колонок и листов без учета регистра (защита от сбоев при переименовании).
- Жестко зафиксированы целевые папки Google Диска (`FOLDER_ARTIKEL_ID` и `FOLDER_FARBEN_ID`), исключено случайное сохранение фото в корень Диска.
- Реализованы вспомогательные инструменты таблицы: генератор цветных превью (`dummyimage`) и пакетная синхронизация фото из Диска.
- Автоматически разделены и раскопированы составные файлы чертежей на Диске (строгий контракт `[artikel_nr].png/jpg`).

### 3. Двухконтурная архитектура, офлайн и стабильность
- Настроен Service Worker (`sw.js`) с разделением кэша: оболочка (`heroal-shell-v370`) и медиа-чертежи (`heroal-media-v2`).
- Защищено runtime-кэширование изображений: строгая проверка `Content-Type: image/` перед сохранением в `heroal-media-v2`.
- Реализована локальная база IndexedDB (`heroal_warehouse_db`, v4): монолитный кэш каталога, оверлей переводов и очередь неотправленных фото (`photoQueue`).
- Инфраструктура i18n переведена строго на 3 рабочих языка: DE (основной), EN, RU (с автоматической валидацией словаря).
- Закреплены строгие правила архитектуры и разработки в `.cursorrules`.

### 4. Разгрузка терминалов при поиске и оптимизация памяти
- Реализована утилита `debounce` (150 мс) с поддержкой принудительного сброса `.flush()` для `#find-prof`, `#find-color` и `#find-guide`.
- Обеспечен мгновенный сброс списков при нажатии кнопок Clear и клавиши `Escape`.
- **Изоляция фото в IndexedDB:** полностью устранено дублирование base64-строк в оперативной памяти (`appDB`) и снимках `heroal_db`. Неотправленные снимки хранятся исключительно в виде бинарных `Blob` в `photoQueue`, а превью рендерятся через легковесные `URL.createObjectURL`.
- **Предвычисленные поисковые индексы (RAM):**
  - Развернуты плоские нормализованные индексы для каталогов `ARTIKEL`, `FARBEN` и `AUSKUNFT`.
  - Поиск переведен на токенизацию по схеме `AND` (учет всех слов запроса независимо от порядка).
  - В индекс артикулов включены технические размеры `masse_de` и описания.
  - Реализован приоритетный подъем точного номера артикула/кода цвета на 1-ю позицию выдачи (`promoteExactKey`).
  - Обеспечен автоматический жизненный цикл пересборки индексов: при `seed`, загрузке из IndexedDB и завершении синхронизации.

### 5. Устойчивое кэширование медиа (Chunked Precache)
- Реализована пакетная предзагрузка чертежей в хранилище `heroal-media-v2` порциями по 6 параллельных потоков с задержкой 120 мс между пачками.
- Внедрена предварительная проверка через `cache.match()`: повторный синк не обращается к сети за уже закэшированными файлами.
- Обеспечена отказоустойчивость: обрыв отдельного соединения не прерывает очередь, процесс защищен через `AbortController` и транслирует прогресс в UI.

### 6. Сквозное автоматизированное тестирование (E2E на Playwright)
- Развернут тестовый контур на Playwright с автозапуском локального веб-сервера.
- Автоматизирована регулярная валидация 3 критических контуров:
  - Авторизация по PIN (`1111`) с проверкой профиля/роли в шапке.
  - Загрузка оболочки через Service Worker и поиск артикула при 100% отключении сети.
  - Сохранение фото в бинарную очередь `photoQueue` IndexedDB в режиме офлайн без сбоев интерфейса.

### 7. Изоляция сетевого слоя (Data Provider Abstraction)
- Создан единый фасад `DataProvider` (`fetchCatalog`, `uploadPhoto`).
- Реализован `GoogleSheetsDataProvider`: парсинг CSV, нормализация строк и вызовы Apps Script полностью вынесены из UI и служб приложения.

### 8. Подготовка под локальный сервер (Self-Hosted Turnkey Kit)
- Развернут комплект `server-kit/` для мгновенного развёртывания PocketBase / SQLite (`schema.json`, `migrate-csv.js`, `README.md`).
- Реализован альтернативный `LocalServerDataProvider` с поддержкой PocketBase REST API и multipart-отправки файлов.
- Внедрен глобальный флаг переключения `CONFIG.DATA_SOURCE` (`GOOGLE` / `LOCAL`) без необходимости пересборки приложения.

### 9. Устранение ошибок консоли DevTools и аудит чистоты рантайма (v370)
- Отфильтрованы пустые, `N/A`, `null`/`undefined` и невалидные URL до precache и до `<img src>`, чтобы консоль не заполнялась 404.
- Ссылки Google Drive (`thumbnail` / `file/d`) нормализуются в CORS-эндпоинт `lh3.googleusercontent.com` и на странице, и в Service Worker.
- Обработчик `fetch` в `sw.js` больше не роняет воркер необработанным исключением: сеть и промах кэша дают аккуратный fallback.
- `JSON.parse`, IndexedDB/LocalStorage и обращения к DOM-узлам обёрнуты в безопасные проверки/`try/catch`; сбои загрузки чертежей пишутся в `console.debug`.
- Приведён в порядок `manifest.json`: валидный `id` = `start_url`, `theme_color` `#003a79`, иконки 192/512 с фактическими размерами PNG и `purpose` (`any` / `maskable`). Мелкие favicon остаются только в HTML.

## 🎯 Статус проекта
Инженерный фундамент готов для стабильной промышленной эксплуатации на складских терминалах в режиме PWA. Дальнейшие доработки могут носить точечный характер (добавление новых полей в таблицы, локализация интерфейса или включение локального сервера при необходимости).

## 🔮 Перспективы и точки роста (Чего не хватает для масштабирования)

Ниже — конкретные задачи, которые уже видны по текущей архитектуре (монолитный `index.html`, IndexedDB v4, двухконтурный SW, `DataProvider`, очередь `photoQueue`). Это не ломает текущий контракт, а описывает следующий контур зрелости.

### Сканирование штрихкодов / DataMatrix камерой терминала
- Поле `barcode` уже попадает в RAM-индекс артикулов, но ввод — только PIN/OSK и физическая клавиатура.
- Нужен контур **Hardware Barcode Scanner API / `BarcodeDetector`**: живой видоискатель (как у фотозахвата), разбор DataMatrix/EAN/Code128, подстановка в `#find-prof` / `#photo-id`.
- Для промышленных USB/HID-сканеров (режим клавиатурного клина) — отдельный буфер scan-gap, чтобы пачка символов не разбивалась debounce 150 мс и не уходила в «частичный» поиск.
- Fallback: если `BarcodeDetector` недоступен, не блокировать терминал — оставить ручной ввод.

### Автоматический фоновый Sync при восстановлении сети
- Сейчас тихий синк: 2.5 с после старта, каждые 12 минут и по `window.online`. Этого мало в фоне вкладки и после kill PWA.
- Подключить **Background Sync API** (и при наличии — Periodic Background Sync) в `sw.js` для `fetchCatalog` + докачки чертежей и flush `photoQueue`, с тем же дедлайном 120 с и без полной перекачки `heroal-media-v2`.
- Сохранять `navigator.onLine` как быстрый фильтр, но не как истину: регистрировать sync-тег при офлайн-ошибке CSV/фото и повторять, когда браузер считает сеть устойчивой.
- Не открывать модалку прогресса из фона — только бейдж «syncing» / «synced», как у текущего silent-контура.

### Управление дисковой квотой StorageManager
- `navigator.storage.persist()` уже запрашивается, но оператор не видит, сколько места съели чертежи.
- Нужен монитор `navigator.storage.estimate()` (usage / quota) в настройках: предупреждение при заполнении >80%, оценка «сколько ещё артикулов влезет», кнопка точечной очистки только битых записей media-кэша (не всего `heroal-media-v2`).
- Политика вытеснения: LRU по URL, которых нет в текущем каталоге (pruning уже есть) + отказ писать в кэш при `QuotaExceededError` без падения UI.
- Отдельно считать `photoQueue` (Blob) vs оболочка vs чертежи, чтобы очередь фото не вытесняла offline-чертежи.

### Каталог, медиа и наблюдаемость
- Хостинг чертежей на Drive/`lh3` остаётся единственной хрупкой зависимостью (429, смена URL). Для масштаба цеха — свой CDN/статика рядом с PWA, с теми же CORS-проверяемыми ответами.
- Дифференциальный CSV-синк (ETag / размер / хеш вкладки), чтобы не качать все четыре таблицы целиком каждые 12 минут.
- Телеметрия терминала без PII: версия оболочки, `PERSISTED`, доля чертежей в кэше, последние коды abort (`network` / `timeout`) — в служебный лист, не в `console`.
- Целостность медиа: не кэшировать ответ без `image/*`, опционально сверять короткий хеш/размер с колонкой таблицы.

### Продуктовый контур склада
- Роли UI: упаковщик / мастер / админ (фото и настройки уже частично завязаны на роль) — скрыть GAS-URL и опасные кнопки на обычном PIN.
- Этикетки/печать: шаблон packing-slip по `artikel_nr` + цвет без ухода в ERP.
- Конфликт `photoQueue`: повторная отправка, ручной retry, индикатор «N фото ждут сеть» в шапке постоянно, не только после открытия камеры.
- Мультисклад / несколько Google-таблиц в одном терминале без перетирания IndexedDB.

### Качество поставки
- Расширить Playwright за пределы трёх smoke-тестов: i18n-переключатель, офлайн-цвета, abort precache, overflow IndexedDB.
- CSP в `index.html` (GAS + `lh3` + `docs.google.com` в allowlist), чтобы случайный скрипт из CSV не исполнился.
- Не дробить монолит сборщиком (запрещено правилами), но можно вынести «живые» регрессионные фикстуры CSV в `tests/fixtures` без изменения runtime.
